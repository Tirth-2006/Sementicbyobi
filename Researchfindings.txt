1. PROJECT OBJECTIVE
--------------------

The project investigates whether repeated answers from a language model can
be grouped by meaning and used to estimate uncertainty related to
hallucination.

The implementation is inspired by the semantic entropy method described by
Farquhar et al. It is an adaptation using a local Qwen3-1.7B model, TriviaQA,
and a DeBERTa NLI model.

- Hidden states

The token entropy calculation is based on the next-token probability
distribution:

H_token = -sum(p(token) * log(p(token)))

This is token-level entropy. It is not the same as semantic entropy.
Extracting token probabilities and hidden states does not by itself mean that
the full semantic entropy estimator from the paper has been implemented.

8. ANSWER CLUSTERING
--------------------

Clustering is implemented in:

cluster_answers.py

The script reads the existing Qwen JSON output. It does not rerun Qwen.

For each pair of answers, it creates:

Question: [question]
Answer: [answer A]

and:

Question: [question]
Answer: [answer B]

The NLI model evaluates both directions.

Two answers are considered mutually entailing only when:

- A -> B is labelled "entailment"
- B -> A is labelled "entailment"
- Both scores are at least 0.5

Current clustering rule:

- Greedy complete-linkage clustering.
- An answer joins a cluster only if it mutually entails every current member
  of that cluster.
- If no cluster is compatible, a new cluster is created.
- The first compatible cluster is selected.

This is stricter than connected-component or Union-Find clustering because it
does not merge answers merely through a transitive chain:

A <-> B
B <-> C
A not equivalent to C

However, it is still greedy and order-dependent. Different answer orders can
produce different assignments. It is not a globally optimized clustering
algorithm.

11. SHANNON ENTROPY
--------------------

The script calculates Shannon entropy over the empirical frequencies of the
semantic clusters:

H = -sum(p_i * ln(p_i))

where:

p_i = cluster size / total number of answers

For bb_6487:

Cluster sizes:
[5, 2, 1, 1, 1]

Probabilities:
[0.5, 0.2, 0.1, 0.1, 0.1]

Entropy:

H = 1.359237 nats

The natural logarithm is used by Python's math.log(), so the unit is nats.
If log base 2 were used, the unit would be bits instead.

Reference bounds for 10 answers:

- One cluster containing all answers: H = 0 nats
- Ten separate clusters: H = ln(10) = 2.302585 nats

The current value of 1.359237 nats indicates that the answers are spread
across several clusters, with one cluster containing half of the responses.

13. IMPORTANT SCOPE LIMITATIONS
--------------------------------

These are limitations of what has been measured so far. They are not errors
in the working code and they do not mean that the project is broken.

13.1 Frequency estimate, not the paper's full estimator

The current entropy calculation counts how many answers fall into each
cluster and applies Shannon entropy to those frequencies. It is therefore a
frequency-based estimate.

The paper's full semantic entropy method uses probability information from
the language model, such as the likelihood of each generated answer, and
aggregates that probability mass by semantic cluster. The current pipeline
does not yet use those answer-level likelihoods for the cluster calculation.
The current value describes answer disagreement, but it is not the full
probability-weighted estimator from the paper.

13.2 Clustering quality has only been checked on one question

The NLI model runs and gives sensible results for several obvious pairs.
However, clustering has only been inspected in detail for question bb_6487.

For that question, the model grouped "Vessels" with "vascular tissue".
That may be reasonable in the plant-biology context, but it is not
automatically correct merely because DeBERTa predicted entailment. NLI
predictions are model judgments and can be mistaken.

The current clustering method is also greedy and order-dependent. Therefore,
the inspected result does not establish that clusters accurately represent
meaning across all 100 questions.

13.3 Detection performance has not been measured

The project has not yet tested whether a higher entropy value actually
corresponds to a factual error across the 100 questions.

For bb_6487, all 10 generated answers were incorrect and the measured
frequency-based entropy was 1.359237 nats. This is one example only. It does
not establish a general relationship between entropy and correctness.

13.4 Adaptation rather than exact reproduction

The current implementation is a Qwen3-based adaptation inspired by the paper
and reference repository. It does not reproduce every model, probability
calculation, storage format, or evaluation step from the original project.

The verified current workflow is:

Generated responses
-> NLI pairwise comparisons
-> Greedy complete-linkage semantic clusters
-> Shannon entropy over cluster frequencies

This means the project is functioning at the level that has been tested:
generation, NLI comparison, clustering for one inspected question, and
frequency-based entropy calculation. The statements above identify what the
current experiments do not yet prove.

The script evaluate_order_sensitivity.py tested whether greedy clustering

data\generated\trivia_qa_qwen3_20261024_162539_clusters.json

No NLI inference or GPU computation was repeated. For each of the 100

Results:

- Questions with at least one changed partition: 7/100 (7.0%)
- Total shuffled runs: 100,000
- Runs with a changed partition relative to the original order: 2,696
  (2.696%)
- Mean per-question entropy range: 0.008329 nats
- Maximum per-question entropy range: 0.347929 nats

Five questions showed actual entropy variation. The other two affected
questions produced different partitions with the same cluster-size

For bb_6487 specifically:

- Original entropy: 1.359237 nats
- Shuffled entropy range: 1.359237 to 1.504788 nats
- Maximum increase: 0.145552 nats
- Changed partition rate: 27.8% of sampled permutations

The result confirms that the current estimator is not completely
order-invariant. In this sample, order dependence was uncommon overall, but

entropy for individual questions. Therefore, entropy should be interpreted
with this algorithmic stability limitation in mind.

15. COMPARISON WITH AN ORDER-INDEPENDENT METHOD
------------------------------------------------

The script compare_clustering_methods.py compared the current greedy
complete-linkage method with connected components of the same mutual-
entailment compatibility graph. The comparison reused the saved pairwise
NLI decisions and did not rerun NLI inference.

Connected components are order-independent: every answer connected by a path
of compatible edges is placed in the same component. This removes the
processing-order problem, but it can create transitive-bridge errors. For
example, A compatible with B and B compatible with C can merge A and C even
when A and C are not mutually compatible.

Partition and entropy results:

- Different partitions: 7/100 questions (7.0%)
- Mean greedy entropy: 1.135527 nats
- Mean connected-component entropy: 1.116148 nats
- Mean component-minus-greedy entropy change: -0.019379 nats
- Maximum absolute entropy change: 0.381909 nats

For every question whose partition changed, connected components produced
equal or lower entropy because it merged compatible paths into larger
components. For bb_6487, the greedy cluster sizes were [5, 2, 1, 1, 1],
whereas connected components produced [6, 2, 1, 1], reducing entropy from
1.359237 to 1.088900 nats.

Downstream metrics using low-temperature exact-match correctness:

                       AUROC       AURAC
Greedy complete-linkage 0.841705     0.462878
Connected components    0.838407     0.465753

The order-independent method slightly improved AURAC (+0.002875) but
slightly reduced AUROC (-0.003298). This is not evidence that connected
components are semantically better. It demonstrates a methodological
tradeoff: order invariance can be obtained at the cost of potentially
over-merging answers through transitive bridges.

Output:

data\generated\trivia_qa_qwen3_20261024_162539_clustering_comparison.json


12. HIDDEN-STATE PREDICTIVE EVALUATION
---------------------------------------

The hidden-state predictive evaluation was implemented in:

- evaluate_hidden_state_predictive.py

The evaluation used the saved question-level hidden-state features with
shape (100, 29, 4, 2048), the separate low-temperature correctness labels,
semantic entropy, and token entropy. Exact question_id joins were verified
across all input artifacts. The hidden-state validator passed, all features
were finite, and the correctness counts were 27 correct and 73 incorrect.
The original NPZ, CSV, JSON, and correctness artifacts were not rewritten.

Each question was treated as one independent sample. The evaluation covered
235 configurations:

- 116 hidden-state-only configurations (29 hidden-state indices x 4 pooling
  strategies)
- Semantic entropy alone
- Token entropy alone
- Semantic entropy plus token entropy
- 116 hidden-state plus both entropy features configurations

Every configuration used nested stratified question-level cross-validation.
The outer and inner splits each used 2 folds because the 235 high-dimensional
configurations made larger fold budgets impractical in the available
environment. Logistic regression used a StandardScaler inside the training
pipeline, and regularization was selected only within the outer training
fold using C values [0.1, 1.0]. Out-of-fold probabilities were converted to
uncertainty as 1 - P(correct).

Metrics included incorrectness AUROC, AURAC, Spearman correlation between
uncertainty and correctness, and thresholded classification metrics at
P(correct) = 0.5. Confidence intervals used 100 question-level bootstrap
resamples with seed 20261106. Because 116 hidden-state configurations were
screened, the highest observed configuration is descriptive and is not
treated as statistically superior without multiplicity-aware testing.

The baseline point estimates were:

- Semantic entropy: AUROC 0.8382, AURAC 0.4796, Spearman -0.5210
- Token entropy: AUROC 0.8021, AURAC 0.4794, Spearman -0.4647
- Semantic plus token entropy: AUROC 0.8219, AURAC 0.4947, Spearman -0.4951

Using float64 dispersion arithmetic across all 100 questions gave a minimum
