1. PROJECT OBJECTIVE
--------------------

The project investigates whether repeated answers from a language model can
be grouped by meaning and used to estimate uncertainty related to
hallucination.

The implementation is inspired by the semantic entropy method described by
Farquhar et al. It is an adaptation using a local Qwen3-1.7B model, TriviaQA,
and a DeBERTa NLI model.

5. QWEN TOKEN-LEVEL TEST
------------------------

test_qwen.py verified that the model can expose:

- Generated text
- Token logits
- Token log probabilities
- Token-level entropy
- Hidden states
- A pooled hidden-state representation

The token entropy calculation is based on the next-token probability
distribution:

H_token = -sum(p(token) * log(p(token)))

This is token-level entropy. It is not the same as semantic entropy.
Extracting token probabilities and hidden states does not by itself mean that
the full semantic entropy estimator from the paper has been implemented.

8. ANSWER CLUSTERING
--------------------

Clustering is implemented in:

cluster_answers.py

The script reads the existing Qwen JSON output. It does not rerun Qwen.

For each pair of answers, it creates:

Question: [question]
Answer: [answer A]

and:

Question: [question]
Answer: [answer B]

The NLI model evaluates both directions.

Two answers are considered mutually entailing only when:

- A -> B is labelled "entailment"
- B -> A is labelled "entailment"
- Both scores are at least 0.5

Current clustering rule:

- Greedy complete-linkage clustering.
- An answer joins a cluster only if it mutually entails every current member
  of that cluster.
- If no cluster is compatible, a new cluster is created.
- The first compatible cluster is selected.

This is stricter than connected-component or Union-Find clustering because it
does not merge answers merely through a transitive chain:

A <-> B
B <-> C
A not equivalent to C

However, it is still greedy and order-dependent. Different answer orders can
produce different assignments. It is not a globally optimized clustering
algorithm.

11. SHANNON ENTROPY
--------------------

The script calculates Shannon entropy over the empirical frequencies of the
semantic clusters:

H = -sum(p_i * ln(p_i))

where:

p_i = cluster size / total number of answers

For bb_6487:

Cluster sizes:
[5, 2, 1, 1, 1]

Probabilities:
[0.5, 0.2, 0.1, 0.1, 0.1]

Entropy:

H = 1.359237 nats

The natural logarithm is used by Python's math.log(), so the unit is nats.
If log base 2 were used, the unit would be bits instead.

Reference bounds for 10 answers:

- One cluster containing all answers: H = 0 nats
- Ten separate clusters: H = ln(10) = 2.302585 nats

The current value of 1.359237 nats indicates that the answers are spread
across several clusters, with one cluster containing half of the responses.

13. IMPORTANT SCOPE LIMITATIONS
--------------------------------

These are limitations of what has been measured so far. They are not errors
in the working code and they do not mean that the project is broken.

13.1 Frequency estimate, not the paper's full estimator

The current entropy calculation counts how many answers fall into each
cluster and applies Shannon entropy to those frequencies. It is therefore a
frequency-based estimate.

The paper's full semantic entropy method uses probability information from
the language model, such as the likelihood of each generated answer, and
aggregates that probability mass by semantic cluster. The current pipeline
does not yet use those answer-level likelihoods for the cluster calculation.
The current value describes answer disagreement, but it is not the full
probability-weighted estimator from the paper.

13.2 Clustering quality has only been checked on one question

The NLI model runs and gives sensible results for several obvious pairs.
However, clustering has only been inspected in detail for question bb_6487.

For that question, the model grouped "Vessels" with "vascular tissue".
That may be reasonable in the plant-biology context, but it is not
automatically correct merely because DeBERTa predicted entailment. NLI
predictions are model judgments and can be mistaken.

The current clustering method is also greedy and order-dependent. Therefore,
the inspected result does not establish that clusters accurately represent
meaning across all 100 questions.

13.3 Detection performance has not been measured

The project has not yet tested whether a higher entropy value actually
corresponds to a factual error across the 100 questions.

For bb_6487, all 10 generated answers were incorrect and the measured
frequency-based entropy was 1.359237 nats. This is one example only. It does
not establish a general relationship between entropy and correctness.

13.4 Adaptation rather than exact reproduction

The current implementation is a Qwen3-based adaptation inspired by the paper
and reference repository. It does not reproduce every model, probability
calculation, storage format, or evaluation step from the original project.

The verified current workflow is:

Generated responses
-> NLI pairwise comparisons
-> Greedy complete-linkage semantic clusters
-> Shannon entropy over cluster frequencies

This means the project is functioning at the level that has been tested:
generation, NLI comparison, clustering for one inspected question, and
frequency-based entropy calculation. The statements above identify what the
current experiments do not yet prove.
