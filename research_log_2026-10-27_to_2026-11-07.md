# Research Log: Semantic Entropy and LLM Uncertainty Experiments

> **Document type:** Historical research log  
> **Coverage:** 27 October 2026 – 7 November 2026  
> **Project:** LLM uncertainty signals for correctness prediction  
> **Model:** Qwen3-1.7B  
> **Dataset:** TriviaQA (`unfiltered.nocontext`)  
> **Research reference:** Farquhar et al., *Detecting Hallucinations in Large Language Models Using Semantic Entropy* (Nature, 2024)

This document preserves the development notes, implementation checks, exploratory examples, and experimental findings recorded during the project. It is an archival research log, not the authoritative current project overview. For the current methodology and consolidated results, see [`../research_summary.md`](../research_summary.md) and the repository [`README.md`](../../README.md).

The project is an **experimental adaptation** inspired by semantic entropy research. The empirical cluster-frequency entropy used in the primary pipeline is not an exact reproduction of Farquhar et al.'s probability-weighted semantic entropy estimator.

---

## 1. Project objective

The project investigates whether repeated answers from a language model can be grouped by meaning and whether uncertainty signals derived from those answers and internal model representations can help predict the correctness of a separate answer.

The initial implementation used:

- A local Qwen3-1.7B model.
- TriviaQA questions without context.
- A DeBERTa NLI model for question-conditioned answer comparisons.
- Greedy complete-linkage clustering based on bidirectional entailment.
- Shannon entropy over empirical semantic-cluster frequencies.

The work later expanded to token predictive entropy, hidden-state representations, supervised predictive probes, and within-question hidden-state dispersion.

## 4. Initial token-level model verification

The original local Qwen test verified that the model could expose:

- Generated text.
- Token logits.
- Token log probabilities.
- Token-level predictive entropy.
- Hidden states.
- A pooled hidden-state representation.

The final hidden-state tensor returned by the tested model had a hidden dimension of 2,048. The model returned 29 hidden-state indices in that test.

For a next-token probability distribution \(P(v\mid x_{\lt t})\), token predictive entropy is:

$$
H_t=-\sum_{v=1}^{V}P(v\mid x_{\lt t})\ln P(v\mid x_{\lt t}).
$$

Token predictive entropy and semantic entropy are different quantities. Extracting token probabilities and hidden states does not, by itself, implement the full probability-weighted semantic entropy estimator from the reference paper.

The current token-entropy implementation reconstructs saved answers under teacher forcing and uses raw full-vocabulary softmax probabilities. It does not recover the original top-k/top-p-filtered generation-time distribution.

## 7. NLI clustering method

For each unordered pair of generated answers, the NLI model receives question-conditioned premise and hypothesis strings. The pair is considered mutually entailing only when:

- A → B is labelled `entailment`.
- B → A is labelled `entailment`.
- Both entailment scores are at least 0.5.

The clustering procedure is **greedy first-compatible complete linkage**:

1. Process answers in their current order.
2. Check a candidate answer against every member of an existing cluster.
3. Add the answer to the first cluster for which all pairwise compatibility checks pass.
4. If no cluster is compatible, create a new cluster.

For ten answers, the number of unordered pairs is:

$$
\binom{10}{2}=\frac{10\cdot9}{2}=45.
$$

The implementation evaluates all 45 pairs, with both directions checked for every pair, before assigning clusters. This avoids reducing the pair count through early stopping during cluster formation.

This method is stricter than connected-components clustering because it does not merge answers merely through a transitive chain. However, the greedy first-compatible assignment remains order-dependent and is not a globally optimized clustering algorithm.

## 9. Frequency-based Shannon entropy for `bb_6487`

The implementation calculates entropy over empirical semantic-cluster frequencies:

$$
p_i=\frac{|C_i|}{N},
$$

$$
H_{\mathrm{emp}}=-\sum_i p_i\ln p_i.
$$

For `bb_6487`, the cluster sizes were `[5, 2, 1, 1, 1]`, giving empirical probabilities:

$$
[0.5,0.2,0.1,0.1,0.1].
$$

The recorded entropy was:

$$
H_{\mathrm{emp}}=1.359237\ \text{nats}.
$$

Natural logarithms are used by Python's `math.log()`, so the unit is nats.

Reference bounds for ten answers:

- One cluster containing all answers: \(H=0\) nats.
- Ten separate clusters: \(H=\ln(10)=2.302585\) nats.

The value 1.359237 nats describes the spread of this question's ten sampled answers across the empirical clusters. It does not, on its own, establish a general relationship between entropy and correctness.

## 11. Clustering order-sensitivity experiment

The script `scripts/analysis/evaluate_order_sensitivity.py` tested whether greedy clustering changes when the same answers are processed in a different order.

The experiment reused the saved pairwise NLI decisions from the generated clustering artifact. No NLI inference or GPU computation was repeated. For each of the 100 questions, 1,000 deterministic answer permutations were generated using seed `20261102`. Each permutation used the same first-compatible complete-linkage assignment rule as the primary clustering implementation.

Recorded results:

| Measure | Result |
|---|---:|
| Questions with at least one changed partition | 7 / 100 (7.0%) |
| Total shuffled runs | 100,000 |
| Runs with changed partition relative to original order | 2,696 (2.696%) |
| Mean per-question entropy range | 0.008329 nats |
| Maximum per-question entropy range | 0.347929 nats |

Five questions showed actual entropy variation. Two additional questions had different partitions with the same cluster-size distribution, so their entropy did not change.

For `bb_6487`:

- Original entropy: 1.359237 nats.
- Shuffled entropy range: 1.359237 to 1.504788 nats.
- Maximum increase: 0.145552 nats.
- Changed partition rate: 27.8% of sampled permutations.

The result confirms that the greedy estimator is not completely order-invariant. Order dependence was uncommon across the full sample but substantial for a small subset of questions and could materially alter entropy for individual questions.

## 12. Comparison with connected-components clustering

The script `scripts/semantic/compare_clustering_methods.py` compared greedy complete linkage with connected components using the same mutual-entailment compatibility graph. It reused saved pairwise NLI decisions and did not rerun NLI inference.

Connected components are order-independent: every answer connected by a path of compatible edges is placed in the same component. This removes processing-order dependence but can create transitive-bridge errors. For example, A compatible with B and B compatible with C can merge A and C even when A and C are not mutually compatible.

Recorded partition and entropy results:

| Measure | Result |
|---|---:|
| Questions with different partitions | 7 / 100 (7.0%) |
| Mean greedy entropy | 1.135527 nats |
| Mean connected-components entropy | 1.116148 nats |
| Mean component-minus-greedy entropy change | -0.019379 nats |
| Maximum absolute entropy change | 0.381909 nats |

For every question whose partition changed, connected components produced equal or lower entropy because it merged compatible paths into larger components.

For `bb_6487`:

- Greedy cluster sizes: `[5, 2, 1, 1, 1]`.
- Connected-components cluster sizes: `[6, 2, 1, 1]`.
- Greedy entropy: 1.359237 nats.
- Connected-components entropy: 1.088900 nats.

Downstream metrics using the separate low-temperature exact-match correctness labels:

| Clustering method | AUROC | AURAC |
|---|---:|---:|
| Greedy complete linkage | 0.841705 | 0.462878 |
| Connected components | 0.838407 | 0.465753 |

Connected components slightly increased AURAC by 0.002875 and slightly reduced AUROC by 0.003298. This does not establish that connected components are semantically better. It shows a methodological trade-off between order invariance and possible over-merging through transitive bridges.

## 13. Hidden-state predictive evaluation

The main predictive-probe evaluator is [`scripts/evaluation/evaluate_hidden_state_predictive.py`](../../scripts/evaluation/evaluate_hidden_state_predictive.py).

The evaluation used saved question-level hidden-state features with shape `(100, 29, 4, 2048)`, the separate low-temperature correctness labels, semantic entropy, and token entropy.

The input audit checked exact `question_id` joins across the artifacts. The hidden-state validator passed, all features were finite, and the target counts were 27 correct and 73 incorrect.

Each question was treated as one independent sample. The evaluation covered 235 configurations:

- 116 hidden-state-only configurations (29 hidden-state indices × 4 pooling strategies).
- Semantic entropy alone.
- Token entropy alone.
- Semantic entropy plus token entropy.
- 116 hidden-state-plus-both-entropy configurations.

Every configuration used nested question-level stratified cross-validation:

- Outer folds: 2.
- Inner folds: 2.
- Shuffling enabled.
- Random seed: `20261106`.
- `StandardScaler` inside the training-fold pipeline.
- Logistic regression with `lbfgs` and `max_iter=1000`.
- Regularization selected within the outer training fold from \(C\in\{0.1,1.0\}\), using inner-fold AUROC.
- Out-of-fold uncertainty: \(1-P(\mathrm{correct})\).

Metrics included incorrectness AUROC, AURAC, Spearman correlation between uncertainty and correctness, and thresholded classification metrics at \(P(\mathrm{correct})=0.5\).

The initial 235-configuration screening used 100 question-level bootstrap resamples with seed `20261106`. Because 116 hidden-state configurations were screened, the highest observed configuration is descriptive and is not treated as statistically superior without multiplicity-aware testing.

## 14. Post-token hidden-state dispersion

Post-token hidden-state dispersion was evaluated as a separate question-level feature.

The post-token extractor selected hidden states at answer-token positions `p`, rather than the causal predictor positions `p-1` used by the original predictor-state extraction. It used hidden-state index 28 and mean pooling, and saved separate artifacts.

Recorded dimensions:

- Per-answer vectors: `(1000, 2048)`.
- Question-level feature vectors: `(100, 2048)`.

Mapping, finite-value, and aggregation validation passed with zero failures.

The dispersion statistic for ten answer vectors \(z_{q,r}\) is the mean Euclidean distance from their centroid:

$$
\mu_q=\frac{1}{10}\sum_{r=1}^{10}z_{q,r},
$$

$$
D_q=\frac{1}{10}\sum_{r=1}^{10}
\left\|z_{q,r}-\mu_q\right\|_2.
$$

Using float64 arithmetic across all 100 questions gave:

| Statistic | Value |
|---|---:|
| Minimum | 0.000000 |
| Maximum | 53.857150 |
| Mean | 29.446883 |
| Median | 34.577319 |
| Standard deviation | 16.672374 |
| Questions with exactly zero dispersion | 15 |

The standalone raw post-token dispersion evaluation reported:

| Metric | Point estimate |
|---|---:|
| Spearman vs correctness | -0.397458 |
| AUROC for incorrectness | 0.757991 |
| AURAC | 0.435888 |

The corresponding 95% question-level bootstrap intervals (20,000 resamples, seed `20261031`) were:

| Metric | 95% interval |
|---|---:|
| Spearman | [-0.560431, -0.207661] |
| AUROC | [0.638400, 0.862871] |
| AURAC | [0.297484, 0.574907] |

As a standalone raw score, post-token dispersion had weaker AUROC point estimates than the two entropy baselines in this sample.

## 15. Incremental predictive value of post-token dispersion

The post-token dispersion predictor was evaluated using the existing question-level nested 2-fold / 2-fold cross-validation protocol.

| Configuration | AUROC | AURAC | Spearman | Accuracy | F1 |
|---|---:|---:|---:|---:|---:|
| Semantic entropy | 0.838153 | 0.479576 | -0.521014 | 0.73 | 0.000000 |
| Token entropy | 0.802131 | 0.479362 | -0.464677 | 0.73 | 0.000000 |
| Semantic + token entropy | 0.821918 | 0.494675 | -0.495109 | 0.77 | 0.342857 |
| Semantic + token + post-token dispersion | 0.832065 | 0.509229 | -0.510715 | 0.77 | 0.488889 |

Adding post-token dispersion increased the numerical AUROC from 0.821918 to 0.832065 and AURAC from 0.494675 to 0.509229. Accuracy remained 0.77.

## 17. Interpretation and limitations

The historical experiments support the following measured observations:

- The NLI pipeline can compare generated answers bidirectionally and produce the recorded clustering decisions.
- Greedy complete-linkage clustering is order-dependent.
- Connected-components clustering removes processing-order dependence but can over-merge through transitive paths.
- Empirical semantic entropy and token predictive entropy both show useful ranking associations on this 100-question sample.
- Hidden-state features and dispersion were evaluated as possible predictive inputs.
- Predictor-state dispersion produced stronger numerical point estimates than post-token dispersion in the tested comparison.

The experiments do **not** establish:

1. A general-purpose or deployed hallucination detector.
2. Human-verified factual correctness for all generated answers.
3. A calibrated uncertainty estimate.
4. Exact reproduction of Farquhar et al.'s probability-weighted semantic entropy.
5. Generalization across independent datasets, model families, checkpoints, or tasks.
6. Statistically established incremental improvement from adding dispersion.
7. A statistically established winner between predictor-state and post-token dispersion.

Important limitations include:

- The main sample contains only 100 questions and 27 correct target labels.
- Only Qwen3-1.7B and one TriviaQA sample were evaluated.
- Exact match is a strict reference-based proxy; valid paraphrases can be labelled incorrect.
- Token logits and hidden states were reconstructed by teacher-forcing saved answers and prompts rather than captured from the original generation-time forward passes.
- Raw full-vocabulary softmax does not reproduce the top-k/top-p-filtered sampling distribution.
- The NLI entailment threshold is a heuristic and has not been calibrated on a large human-labelled dataset.
- Greedy complete linkage is order-dependent.
- The 235-configuration screen introduces selection optimism and was not multiplicity-adjusted.
- The nested 2-fold cross-validation and fixed-OOF bootstrap comparisons are exploratory given the sample size.
